# 个人 Android 记账软件

## Goal

为个人提供方便的 Android 记账工具：快速记录日常收支，支持 CSV/JSON 备份恢复、可选手动同步，并支持把一段自然语言账单自动拆分为使用已有分类和备注的多笔记录。

## Background and confirmed facts

- 现有应用为 Kotlin / Compose / Room Android 应用。金额以整数分存储，币种为 CNY。
- 默认支出分类为餐饮、交通、购物、居家、娱乐、医疗、其他；收入分类为工资、奖金、理财、转账、其他。用户也能输入自定义分类，分类名保存在账目中。证据：`app/src/main/java/com/example/personalbookkeeping/ui/screens/EntryScreen.kt:60`、`app/src/main/java/com/example/personalbookkeeping/domain/model/LedgerEntry.kt:13`。
- 现有批量导入通过 Room 事务提交；可用于整批保存 AI 识别结果。证据：`app/src/main/java/com/example/personalbookkeeping/data/repository/RoomLedgerRepository.kt:82`。
- Git 和 S3 兼容对象存储同步已存在；早期版本把 OSS 排除的历史描述已由 `.trellis/spec/backend/ledger-sync-contract.md:93` 的后续约定替代。
- 本次新增范围为 AI 文字记账。默认连接 DeepSeek，服务 URL、API Key 和模型名由用户配置。2026-11-03 查阅官方文档时示例模型为 `deepseek-flash`。

## Requirements

### Existing ledger baseline

- Android 首发，面向个人日常收支。记录包含收支类型、金额、日期、分类和备注。
- 保留新增、查看、编辑、删除、当月统计、固定格式 CSV/JSON 导入导出。
- 文件导入先完整校验并预览；错误使整次导入回滚；重复记录跳过并汇总。
- Git 与 S3 兼容存储均为可选手动同步；未配置时本地使用；冲突保留所有版本供用户选择。
- 不提供应用运营方账号或托管存储服务。

### AI natural-language bookkeeping

- AI-R01：设置页提供大模型配置入口，默认服务 URL 为 `https://api.deepseek.com`、模型为 `deepseek-flash`，API Key 由用户填写；支持 OpenAI Chat Completions 兼容的 HTTPS 服务。
- AI-R02：首页提供“AI 记账”入口，用户粘贴或输入一段包含多笔账单的文字，点击一次即识别、校验并自动保存全部有效结果，再展示本次新增明细。该流程不增加逐笔确认步骤。
- AI-R03：按收支类型使用默认分类及当前账本已有自定义分类；不让模型创建新分类。无法确定分类时使用对应类型已有的“其他”。备注保留每笔消费或收入的实际描述。
- AI-R04：支持文字中明确给出的收入、支出、金额和日期；未指明收支时按支出处理，未指明日期时使用请求发起时设备本地日期。只保存 CNY 金额，不猜测缺失金额。
- AI-R05：所有返回记录在本地校验通过后，在一个事务中提交。格式、金额、日期等任一错误导致整批不写入。请求失败和取消均不更改已有账目；保存期间阻止重复提交，同一批重试使用稳定记录 ID。
- AI-R06：API Key 使用独立 Android Keystore 密钥加密存储；请求只发送本次输入、可用分类和当前日期，不上传历史账单明细；不把密钥或账单内容写进日志、导出文件或同步文件。
- AI-R07：显示缺少配置、识别中、保存中、成功明细和可操作的失败提示；未配置大模型不影响手动记账。

## Acceptance Criteria

- AC-01：用户能新增收入或支出，填写金额、分类、日期和可选备注。
- AC-02：用户能查看、编辑、删除记录，并查看所选月份统计。
- AC-03：用户能导出包含全部账目字段的固定格式 CSV 和 JSON 文件。
- AC-04：导出再导入保留字段；相同文件再次导入不会产生重复账目。
- AC-05：文件导入预览显示格式错误的行号/字段与原因，错误时本地数据不变。
- AC-06：未配置任何远端时，无需登录或联网即可手动记账和查看本地记录。
- AC-07：配置远端后可手动同步并查看成功、失败或冲突状态。
- AC-08：并发修改保留各版本，由用户选择后完成同步。
- AI-AC01（AI-R01、AI-R07）：保存自定义 URL、模型和 API Key 后重启可继续使用；未配置时 AI 入口说明如何设置。
- AI-AC02（AI-R02、AI-R03、AI-R04）：输入“鸡腿10元晚上吃饭20手机壳10元”，默认生成当天三笔支出：餐饮 10.00 元/备注鸡腿，餐饮 20.00 元/备注晚上吃饭，购物 10.00 元/备注手机壳；合计 40.00 元，流水和首页统计同步更新。
- AI-AC03（AI-R03）：识别结果只能使用对应收支类型的已有分类，包含账本中已有的自定义分类；模糊项目归入“其他”。
- AI-AC04（AI-R04）：明确收入和日期得到保留；0.01、10.20 等金额精确转换为整数分，不经浮点数舍入。
- AI-AC05（AI-R05、AI-R07）：无金额、无效日期、超出精度、畸形或被截断的模型结果、认证错误、超时，均显示错误且新增记录数为零。
- AI-AC06（AI-R05）：连续点击不会并发创建重复账目；重试保存同一已识别批次不重复插入。
- AI-AC07（AI-R06）：凭证以密文保存在应用私有存储中，导出与同步数据中无模型配置或 API Key；识别请求不携带历史账目。

## Out of Scope

- 本次只做文字账单，不做语音、图片/OCR、聊天历史或自动读取支付平台通知。
- 不增加模型代理后端、应用账号、联网搜索、模型自动创建分类或外币换算。
- iOS、自动/后台同步、银行授权拉取、企业会计/报税、预算和多人账本继续留待后续。
- 微信支付与支付宝原始文件的专用解析仍留待后续。

## Risks and Deferred Items

- 模型可能误解语义。自动保存后展示明细，用户可以沿用现有编辑/删除功能更正；本地结构校验不能保证语义完全正确。
- 自定义服务须支持所用的 Chat Completions 和 JSON 输出参数；不同厂商协议适配不属于本次范围。
- 在线识别会使用用户配置的 API 额度；本次输入会发送至该服务。
- DeepSeek 模型名可能变化，因此保持可配置；真实线上识别需由用户配置 Key 后验证，不使用任何仓库外凭证。
- 当前命令行默认 Java 为 8。实现后需选取兼容 JDK 运行 debug 构建、lint 与重点测试，实际验证结果记录到任务验证文档。
